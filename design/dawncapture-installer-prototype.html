安装程序现在将引导你完成 DawnCapture 的安装。

如果 DawnCapture 正在运行，安装程序会在继续之前自动关闭它。

需要 Windows 10 2004（10.0.19041）或更高版本；至少需要有 173 MB 的可用磁盘空间。

1欢迎页（定稿）

完全收口到惯例：正文四句（引导 / 自动关闭 DawnCapture / 系统与空间要求 / 单击下一步），最后一句直接用 Inno 官方原文。原来的「接下来 ① ② ③」已删除——序号步骤是 Web 分步表单的进度指示，安装器欢迎页的惯例只有「单击下一步」，动作清单属于安装前的确认页，已移到 ④。Inno 的「请关闭其他程序」也删了：这个安装不替换被他人占用的共享文件，唯一可能被占用的只有 DawnCapture 自己，`CloseApplications=yes` 已交给 Restart Manager。

  • 同一页里每个信息只说一次：名称与版本只在顶部出现，页脚不重复产品名；发布者并入顶部第二行，与版本同行（都是身份信息）。
  • 四句的来源都是别的安装器已经在用的句子：引导句取 NSIS MUI 的 Welcome 原文，收尾句是 Inno 的 `ClickNext` 原文（一字不差，中英都对过 .isl），系统那句与 `MinVersion` / `DiskSpaceMBLabel` 同源；只有「自动关闭 DawnCapture」是为这台机器写的真话——「请关闭其他程序」那句惯例话在这里不成立，所以换掉。
  • 那句磁盘空间里的 173 MB 不要手写：它等于 Inno 按 `[Files]` 算出的所需空间（页脚与 U1 用同一个数字）。安装器自己会在空间不足时报错，所以这里只是提前告知，数字由构建回填。
  • 「权限」与「数据位置」移到 ③ 安装范围与位置页——用户正在那里选权限，说了才有用；提前一页说是无效信息。
  • 页脚左侧留空，不写任何与顶部重复的文字（Inno 的页脚 spacer 本来也是给「空间不足」这类提示用的）。
  • 不预告后续步骤：NSIS MUI 与 Inno 原生的默认文案都只有引导句 + 单击下一步——欢迎页列清单是 Web 表单的做法。动作清单移到 ④（`[安装(I)]` 之前唯一一页），那里才是惯例放「将执行什么」的位置。
  • 正文短，所以正文整组在剩余空间里居中，收尾句单独占最后一行、贴住页脚分隔线上方：空白被拆到锁排上方与正文下方，而不是堆成一整块。
  • （x64）是整个流程唯一一次出现架构：版本行的职责是说明「你启动的是哪个安装包」，而本项目 x86 / x64 / ARM64 三套分别发行（`distribute.ps1 -Architecture`，`.iss` 里由 `/DAppArch` 决定）。② 到 ⑥、U1 到 U4 只谈范围、任务、进度与结果，重复架构不改变任何决定——② 甚至无从得知旧版的架构，只报新版会变成猜测。
需要 [Code]（约 12 行） WizardImageFile 置空 · InitializeWizard：TBitmapImage(132×132) 挂到 WizardForm.WelcomePage 还必须把 `WelcomeLabel1/2` 的 `Left`/`Width` 挪到页左侧——置空向导图只让左侧不再画图，Inno 的布局不变、标签仍在原位置 其余全部原生 正文四句整段写进 `[Messages]` 的 `WelcomeLabel2`（多行纯文本，Inno 原生支持换行）；删掉步骤行后连静态文本都不需要了，`[Code]` 只剩那张页内大图。

3三选一 + 共用地址框

三个范围选项上下排列，下面的安装位置是共用一个可编辑地址框——这是 Inno 原生「权限单选 + 目录页」合并后的写法。相比每行各配一个框，省下约 100px 高度，而且「路径属于哪个范围」由选中项决定，用户不必在几行里挑一个来改。

  • 界面只说一次：徽章表达权限，地址框表达位置；两条规则不占页面——切换范围会把地址框换成该范围的默认目录；手工改过即视为「自定义位置」（自定义是编辑路径的结果，不是第三个要按的按钮）。

U1卸载确认

平台不给卸载器向导页（实测是致命错误），所以第一屏只能是 Windows 自己的确认提示：我们唯一能控制的是那句话——把「将删除什么、在哪里、多大」写进 `[Messages]` 的 `ConfirmUninstall`，让代价在点下去之前就可见；真正的取舍留给下一页的对话框。

Inno 原生提示 提示框由 `unins000.exe` 自己弹（`Uninstallable=yes` 生成），文案来自 `[Messages]` 的 `ConfirmUninstall` —— 版式、图标、按钮都归平台，我们只写那句话，所以「位置 / 体积」只能并进这句话，不能做成信息表。

U2删除范围（满足「全部卸载」）

不是向导里的一页，而是一个独立的小对话框（`CreateCustomForm`）——卸载器只支持这个形态。默认值按「谁发起」定：人主动卸载 → 默认删程序配置（预勾、可见、可取消）；机器发起（升级时用 `/VERYSILENT` 跑这个卸载器）→ 不弹窗、一律不删。录像永远不预勾，因为它不可逆。

  • 不可逆项用红色语义 + 「不可恢复」徽章（DESIGN.md：红色只留给不可逆操作）；「且不会进入回收站」这条留在侧栏，界面不再多占一行。
  • 两行都带具体路径与体积（等宽字体），用户知道自己删的是什么；「包含热键、输出目录、界面语言、缩略图」这类明细同样留在侧栏——不再出现「录制目录库」这类容易被读成录像目录的词。
  • 配置预勾、录像永不预勾，是因为两者可逆性不同：配置删了只是重设一次热键，录像删了就没了。把不可逆的那个留在用户手里。
需要 [Code]（约 20 行） function InitializeUninstall(): Boolean → CreateCustomForm + TNewCheckBox ×2 + TNewButton(mrOk / mrCancel)（配置预勾、录像不预勾） 卸载器**不支持向导页**（实测：`CreateInputOptionPage` / `CreateCustomPage` 直接致命错误），只有自定义对话框能用；所以这一屏是对话框而不是向导页。 预勾之后静默守卫就是**必需**的：静默/无人值守会取默认值、直接删掉设置，而 ② 升级时正是用 `/VERYSILENT` 跑这个卸载器。静默一律不删；要脚本化清理得显式传参。 CurUninstallStepChanged(usPostUninstall) → DelTree(%LocalAppData%\DawnCapture) [UninstallDelete] 只放静态项（程序文件与快捷方式由 Inno 自动清理） 需要统计 复选框里的文件数与体积在运行时统计（FindFirst/FindNext 累计），无数据时隐藏该行；`.iss` 目前是静态文案，统计尚未实现

项状态依据与做法
U1 确认页（锁排 + 信息表） 版式不可实现，需改设计 卸载器里没有可用的向导页（实测：`CreateCustomPage` 与 `CreateInputOptionPage` 都触发「Cannot call ... during Uninstall」致命错误）。确认只能走 Inno 原生提示，文案来自 `[Messages]` 的 `ConfirmUninstall` —— 也就是说 U1 能保留的只有「将删除什么」这句话，锁排与「位置 / 占用」信息表无法作为一页呈现。
静默路径的默认值 必须有守卫（已实现） 第一项预勾之后，静默/无人值守会取默认值、直接删掉设置——而 ② 升级时正是用 `/VERYSILENT` 跑这个卸载器。所以 `UninstallSilent()` 早退是**必需**而非保险：静默一律不保留删除动作。给 IT 的脚本化清理另开显式开关，不靠静默这个启发式。实测更正：InitializeUninstall 是 Boolean 函数，静默分支的早退曾让 Result 留在默认的 False——卸载器把它读成「中止卸载」，于是静默卸载什么都没删（程序文件、快捷方式、注册表项全部保留），② 的升级清理也因此完全失效。卸载器自己的日志是决定性证据：InitializeUninstall returned False; aborting. 修法是函数开头先 Result := True; 再早退；修复后实测：旧版程序文件与快捷方式被删、设置与录像保留。所以这一行的要求不只针对「预勾」，而是任何早退都不能丢下 Result。
范围问两次 需要改 .iss `PrivilegesRequiredOverridesAllowed` 里的 `dialog` 会在向导启动前先弹 Inno 自己的「为所有用户 / 仅为我」对话框，与 ③ 重复；去掉 `dialog`、只留 `commandline` 即可。
SelectDirBrowseLabel 成为死配置 需要改 .iss ③ 是自定义页，取代了原生目录页，所以 `.iss` 里为它写的中英两条消息永远不显示，应删除或移到自定义页的说明里。
.iss 第 226–228 行[UninstallDelete] 立场 冲突，需以本原型为准并同步 `.iss` 第 226–228 行写的是「卸载保留设置与录像，这不是卸载器该替用户决定的」，与本原型 U2/U4（默认全保留、勾选才删）方向一致但表述不同：原注释读起来像「永不删」，本原型是「用户要求才删」。实现时把注释改成后者，并让 `[Code]` 承担删除。
②③ 与 U1/U4 的实现 ②③ 已实现，U1/U4 仍是计划 卸载数据（U2）**已落地为独立对话框**：`CreateCustomForm` + 两个复选（配置预勾、录像不勾）+ 取消/卸载。实测三条硬约束写进 `.iss` 注释：Inno 6.7.3 的卸载器不允许向导页（`CreateInputOptionPage` / `CreateCustomPage` 直接致命错误），允许自定义对话框；`ShowModal` 在静默下也会阻塞，所以 `UninstallSilent()` 早退是**必需**。静默卸载实测：秒退、不删任何用户数据。② 的注册表检测与升级卸载、③ 的自定义范围页、U4 的结果拼装仍是计划。
删配置会连带删索引 应用侧待办 录制库索引就在配置目录里。默认删配置、保留录像之后，重新安装时应用**必须重扫** `Videos\DawnCapture` 重建索引，否则用户保留下来的录像在库里看不见——这是应用侧的活，不是安装器能解决的。
页内 132px 图片 需要额外 [Code] `WizardImageFile` 置空只让左侧不再画图，Inno 的布局不变、标签不会左移——必须显式把 `WelcomeLabel1/2`（完成页是 `FinishedLabel` 一族）挪到页左侧，否则当初那条空色带会回来。
内页右上角小图 资源缺失 全库没有任何向导小图，`.iss` 也没设 `WizardSmallImageFile`，所以内页现在显示的是 Inno 自带图；需要按 58×58 区域导出 2–3 倍 PNG。
